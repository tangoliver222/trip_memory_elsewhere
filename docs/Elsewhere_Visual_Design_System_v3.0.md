# 0. 本版视觉设计的核心修订（必须先读）

## 0.1 视觉不是给旧页面“加星空和衬线字”，而是服务新的四层产品结构

```text
世界：客观旅行数据与碎片世界
发现：少量高价值关系的显影
Else：跨页面、上下文敏感的环境型助手
我的：用户解释与数据控制
```

不同空间必须拥有不同视觉语法，不能继续使用：

> 黑色背景 + 巨型衬线标题 + 随机粒子 + 一堆相同黑卡片

## 0.2 世界中新增两套最关键的可视化系统

### A. 全部碎片 Fragment Field

它不是普通档案网格，而是一片“有机凌乱、可呼吸、隐藏着秩序”的私人数据世界。

视觉目标：

- 让用户感到所有提交内容都真实存在；
- 远看是城市/时间/地点碎片群；
- 近看是事件和单个原件；
- 搜索和 Else 查询会让相关碎片聚集、高亮或移动到中心；
- 不真正同时渲染所有文件，而使用层级细节保证“感知完整”。

### B. 城市碎片场 City Fragment Field

同样以碎片为核心，但范围更小、关系更密、城市时间与地点更明确。

它不是全碎片场的缩小复制，而是：

- 更强的城市色调；
- 更清楚的旅行时间；
- 更密集的事件与地点连接；
- 更容易进入 City Capsule 和城市探索。

## 0.3 点击碎片统一打开 Fragment Lens

Fragment Lens 是所有页面共享的权威碎片详情。

视觉顺序：

1. 先看到碎片身份和数据；
2. 再看到它连接到哪里；
3. 最后点击“查看原件”进入完整图片/票据。

不再一点击照片就直接全屏，也不根据入口弹出不同页面。

## 0.4 发现使用“碎片集合关系构图”，不是普通发现卡

发现的核心单位不是单个碎片，而是：

> 一组碎片如何共同支撑一个值得重新看一眼的发现。

发现首页与详情必须先展示：

- 原件；
- 日期；
-共同实体；
- 连接；
- 缺口。

标题和 AI 观察后显影。

## 0.5 城市内容压缩为两个主入口和三个探索视角

城市首页主方向：

- City Capsule：阅读与回望；
- 城市探索：数据结构。

城市探索：

- 时间；
- 地点；
- 连接。

视觉上必须完全不同：

- 时间 = 时间轨、阶段、事件群；
- 地点 = 地图、地点群、多次到访；
- 连接 = 节点、证据和关系线。

## 0.6 收件箱不再只是“AI 不确定问题”

视觉上需要清楚支持四个状态：

- 最近入库；
- 需要你判断；
- 正在整理；
- 异常与重复。

并新增“本次入库回执”作为上传后最直接的交付页面。

## 0.7 Else 的视觉角色固定为环境型 Agent

Else 不是客服图标，也不是活泼桌宠。

- 95% 时间安静；
- 与底部导航共享同一个实例；
- 打开抽屉时，Orb 本身移动到抽屉中；
- 不重复渲染；
- 粒子只表达 reading/found/uncertain/conflict/processing；
- 不自动冒文艺气泡。

# 1. 风格定义

## 1.1 一句话视觉定位

> **一座在深夜中逐渐显影的私人旅行档案馆：真实照片、小票、截图和时间在安静空间里慢慢靠近，形成可追溯的记忆关系。**

## 1.2 视觉公式

> **私人档案馆 × 数字考古现场 × 暗房显影 × 微型旅行宇宙 × 日式编辑策展**

各部分承担的意义：

- 私人档案馆：可信、克制、可回源；
- 数字考古：从残留证据恢复上下文；
- 暗房显影：内容逐渐出现，不一次给完答案；
- 微型宇宙：城市与碎片形成空间层级；
- 编辑策展：不对称但有结构，原件位置有意义。

## 1.3 目标感受

用户应该感到：

- 私密；
- 安静；
- 有时间距离；
- 原件真实；
- 世界在缓慢生长；
- 联系正在被发现；
- AI可靠但不强势；
- 页面有艺术感，但所有内容都能理解和操作。

## 1.4 绝对不是

### 不是暗黑科技 Dashboard

禁止：

- 蓝紫霓虹；
- Web3/赛博朋克；
- 神经网络通用背景；
- 满屏扫描线；
- 数据看板；
- 每张卡片发光；
- 科技蓝图标系统；
- “AI处理中”的雷达动画。

### 不是文艺相册模板

禁止：

- 每页大图 + 一句 AI 散文；
- 所有标题都用超大衬线；
- 随机错落照片；
- 模糊文案代替事实；
- 复制同一图片冒充多个时间；
- 每页都像社交媒体长图。

### 不是文件管理器

禁止：

- 全部碎片做成普通九宫格；
- 文件夹树；
- 四个同权大上传框；
- 表格化关系；
- 地点、场景、碎片使用同一媒体卡；
- 大量普通筛选控件占满首屏。

### 不是活泼桌宠

禁止：

- Else 跳动、挥手、随机说话；
- 高频呼吸和闪烁；
- 同页多个 Else；
- 冒出“想起曼谷了吗”；
- 自动推断情绪；
- 长期遮挡内容。

# 2. 记忆心流设计原则

## 2.1 所有记忆页面的固定显影顺序

```text
原始碎片
→ 时间和地点
→ 碎片之间的关系
→ AI 的克制观察
→ 用户操作
→ 用户自己的解释
```

错误顺序：

```text
巨型标题/AI结论
→ 长文
→ 页面底部才有来源
```

## 2.2 每屏只能有一个主要焦点

一屏内最多：

- 一个主要视觉对象；
- 一个主动作；
- 一个次动作；
- 其他动作进入更多菜单。

禁止一屏同时要求用户：

- 保存；
- 命名；
- 追问；
- 看来源；
- 分享；
- 忽略。

## 2.3 留白必须有语义

允许用于：

- 时间跨度；
- 未连接空白；
- 章节停顿；
- 碎片群之间的空间距离；
- 用户理解信息的缓冲。

禁止用于：

- 没有布局内容；
- 盲目追求高级；
- 桌面布局没有正确折叠导致的大空列。

## 2.4 动效必须解释变化

每个动效必须回答至少一个问题：

- 内容从哪里来？
- 它连接到哪里？
- 哪个状态改变？
- 用户现在进入哪一层？
- 哪个对象成为中心？

不解释信息的动效应删除。

# 3. 页面视觉密度

## 3.1 沉浸型

页面：

- 世界首页；
- 城市世界首屏；
- City Capsule；
- 重点发现；
- 发现详情 Hero；
- 跨旅程发现；
- 分享预览。

特征：

- 一屏一焦点；
- 原件主导；
- 较大呼吸空间；
- 操作后置；
- 动效慢；
- 文字少且有层级。

## 3.2 探索型

页面：

- 城市探索；
- 时间视角；
- 地点视角；
- 连接视角；
- 场景详情；
- 地点详情；
- 连接详情；
- 发现列表；
- 全部碎片的近景层级。

特征：

- 图片、结构和证据平衡；
- 信息密度中等；
- 可缩放、筛选和下钻；
- 不使用同款黑卡堆叠。

## 3.3 工具型

页面：

- 导入；
- 本次入库回执；
- 收件箱；
- Fragment Lens；
- 原件详情；
- 搜索和筛选；
- 隐私；
- 存储；
- 删除/冲突；
- 设置。

特征：

- 高对比；
- 低装饰；
- 操作稳定；
- 少粒子；
- 不使用海报式排版；
- 不使用巨型衬线标题。

# 4. 设计 Token

## 4.1 背景与表面

```css
:root {
  --bg-root: #080B0E;
  --bg-deep: #0A0E12;
  --bg-soft: #0D1115;

  --surface-1: #0F1418;
  --surface-2: #141A1F;
  --surface-3: #192026;
  --surface-warm: #191713;
  --surface-overlay: rgba(15, 20, 24, 0.94);

  --line-subtle: rgba(240, 239, 232, 0.09);
  --line-medium: rgba(240, 239, 232, 0.16);
  --line-strong: rgba(240, 239, 232, 0.28);
}
```

规则：

- 不全局使用纯黑；
- 沉浸页面允许蓝灰/暖灰局部光晕；
- 工具页面背景更干净；
- 设置页不铺星图和连接线；
- 遮罩层不能变成桌面全宽大灰板。

## 4.2 文字

```css
:root {
  --text-primary: #F1F0EA;
  --text-secondary: #A1A7AA;
  --text-tertiary: #6F777D;
  --text-disabled: #4D555B;
  --text-warm: #D3C1A7;
  --text-cool: #A7B4C0;
}
```

## 4.3 状态色

低饱和、低面积使用：

```css
:root {
  --state-confirmed: #CBB998;
  --state-suggested: #93A6B6;
  --state-user: #D7C5AA;
  --state-unresolved: #7C858C;
  --state-conflict: #B58A72;
  --state-error: #A96F68;
  --state-processing: #899CAA;
}
```

禁止：

- 大面积鲜绿；
- 红色错误 Banner；
- 高饱和蓝紫；
- 仅靠颜色区分状态。

## 4.4 字体

### 记忆/展示层

```css
font-family:
  "Noto Serif SC",
  "Source Han Serif SC",
  "Songti SC",
  serif;
```

只用于：

- 城市名；
- 发现标题；
- Capsule 章节；
- 用户文字；
- 少数沉浸主标题。

### 界面/信息层

```css
font-family:
  Inter,
  "SF Pro Display",
  "PingFang SC",
  "Noto Sans SC",
  sans-serif;
```

用于：

- 导航；
- 按钮；
- 元数据；
- 证据；
- 时间；
- 地点；
- 设置；
- Else 回答。

### 字号

| 层级 | 移动端 |
|---|---:|
| 城市主标题 | 44–52px |
| 发现详情标题 | 38–46px |
| 普通页面标题 | 30–36px |
| 章节标题 | 24–30px |
| 区块标题 | 18–22px |
| 正文 | 16–17px |
| 操作 | 15–16px |
| 元数据 | 13–14px |
| 证据标签 | 12–13px |

工具页禁止使用 44px 以上衬线标题。

## 4.5 间距

移动端基础：

```css
--space-page: 20px;
--space-immersive: 24px;
--space-tight: 8px;
--space-small: 12px;
--space-medium: 20px;
--space-large: 32px;
--space-section: 56px;
--space-chapter: 72px;
```

- 普通页面横向 20px；
- 沉浸文字 24–28px；
- 图片可局部出血；
- 长页面底部预留导航 + safe area + 32px；
- 横向轨道尾部至少 20px。

## 4.6 圆角

- 原件照片：0–6px；
- 票据：0–4px；
- 信息面板：8–14px；
- Fragment Lens / Bottom Sheet：20–28px；
- 底部导航：24–30px。

禁止所有模块统一 24px 大圆角。

## 4.7 阴影与光

优先使用：

- 深浅层次；
- 细描边；
- 局部光晕；
- 原件本身的高光。

避免：

- 大面积盒阴影；
- 每卡发光；
- 霓虹描边；
- 毛玻璃套毛玻璃。

# 5. 原件材质系统

## 5.1 照片

- 保持真实色彩；
- 允许轻微暗角；
- 不用统一复古滤镜；
- 不过度模糊；
- 支持原始比例；
- 选中时只做轻微亮度和层级变化。

## 5.2 小票/票据

必须像真实票据：

- 保留纸张比例；
- 可见票据边缘；
- 显示日期/商户/OCR 局部；
- 使用非常轻的纸张纹理；
- 不用灰色方块写“FERRY”代替。

## 5.3 截图

- 保留界面或地图特征；
- 可适当裁切隐私部分；
- 与照片材质明显不同；
- 不伪装成普通照片。

## 5.4 菜单

- 保留排版和文字；
- 允许局部特写；
- 可提取菜品文字作为信息层；
- 不只展示食物照片。

## 5.5 文字碎片

- 使用薄纸/注释条感；
- 文字为主；
- 不变成普通聊天气泡。

## 5.6 未决碎片

- 降低饱和；
- 边缘不完整；
- 使用虚线或半透明；
- 内容仍可辨认；
- 禁止模糊成空占位。

# 6. 粒子系统

## 6.1 粒子的产品语义

粒子不是“宇宙装饰”，而是：

- 原件正在显影；
- 两个碎片正在建立联系；
- 同一群内容正在聚集；
- Else 正在读取；
- 用户修正改变了连接。

## 6.2 四类粒子

### A. Ambient Particle

用于：

- 世界地球；
- 城市碎片场；
- Capsule；
- 重点发现。

规格：

- 每屏 8–14 个可见亮点；
- 透明度 0.08–0.22；
- 周期 12–24 秒；
- 大多数近乎静止；
- 不持续闪烁；
- 不组成通用神经网络。

### B. Fragment Particle

从原件边缘产生。

触发：

- 原件首次显影；
- 导入聚拢；
- 碎片被选中；
- 建立连接；
- 进入共同实体。

规格：

- 单次 6–20 个；
- 一次性；
- 颜色从原件取样后降低饱和；
- 不从随机页面坐标产生；
- 不能遮挡原件内容。

### C. Relation Particle

状态：

- 已确认：稳定细线、轻微微光；
- AI 建议：少量粒子缓慢沿线移动；
- 未决：断续线，粒子无法到达终点；
- 冲突：路径分叉；
- 用户修正：旧线淡去，新线绘制。

优先技术：

- SVG Path；
- Web Animations API + `stroke-dasharray` / `pathLength`；
- DOM 节点 + ResizeObserver。

### D. Else Particle

仅在状态变化时：

- `reading`
- `found`
- `uncertain`
- `conflict`
- `processing`

Idle 状态只保留角色内部微光。

# 7. 动效语言

## 7.1 时长

| 类型 | 时长 |
|---|---:|
| 工具反馈 | 160–240ms |
| 卡片/面板展开 | 280–420ms |
| 记忆显影 | 500–900ms |
| 页面共享转场 | 420–700ms |
| 环境漂移 | 12–24s |

禁止阻塞式动画超过 1.2 秒。

## 7.2 缓动

推荐：

- `easeOut` 用于进入；
- `easeInOut` 用于关系流动；
- Spring 只用于轻微拖拽和抽屉，不用于所有卡片弹跳。

## 7.3 记忆显影

标准顺序：

1. 第一张原件显影；
2. 时间出现；
3. 第二张原件出现；
4. 连接绘制；
5. 共同实体出现；
6. 标题最后显影。

## 7.4 滚动

允许：

- 小幅透明度；
- 8–12px 视差；
- 章节进入一次性显影；
- 时间线节点逐个点亮。

禁止：

- 滚动绑架；
- 内容大幅漂移；
- 所有元素持续运动；
- 没有静止参照物。

## 7.5 Reduced Motion

必须支持：

- 地球静止；
- 环境粒子停止；
- 碎片只淡入；
- 关系线直接显示；
- Else 停止呼吸；
- 功能和信息完整保留。

# 8. 全局布局与响应式

## 8.1 AppViewport

移动优先：

```css
.app-viewport {
  position: relative;
  width: 100%;
  max-width: 480px;
  min-height: 100dvh;
  margin-inline: auto;
  overflow-x: clip;
  background: var(--bg-root);
}
```

桌面浏览器只作为居中预览，不把移动页面拉成桌面宽屏。

## 8.2 PageShell

```css
.page-shell {
  min-height: 100dvh;
  padding-inline: 20px;
  padding-top: calc(16px + env(safe-area-inset-top));
  padding-bottom: calc(120px + env(safe-area-inset-bottom));
  overflow-x: clip;
}
```

## 8.3 OverlayHost

所有 Portal、Bottom Sheet、Modal 必须受 AppViewport 最大宽度约束。

禁止直接 `width: 100vw` 横跨浏览器。

## 8.4 Bottom Sheet

```css
.bottom-sheet {
  width: min(100%, 480px);
  max-height: 92dvh;
  margin-inline: auto;
  overflow-y: auto;
  overscroll-behavior: contain;
  border-radius: 24px 24px 0 0;
}
```

## 8.5 视口验收

主：

- 390 × 844；
- 430 × 932。

辅助：

- 768 × 1024；
- 1440 × 1000。

每次必须检查：

- `scrollWidth === clientWidth`；
- 导航不遮挡；
- Sheet 不超容器；
- 文字不截断；
- 主动作可见；
- Else 只有一个；
- 横向轨道可完整滚到最后。

- 最终迁移到世界顶部“全部碎片”；
- Else 仍为中央唯一 Orb。

## 9.2 Else 单实例

一级页面：

- Orb 锚定底部；
- 52–60px；

## 9.3 Else 隐藏

- 原件全屏；
- 地图全屏操作；
- 批量选择；
- 长文本输入；
- 分享预览；

# 10. 核心组件视觉语法

## 10.1 Fragment Node

必须表达：

- 媒介类型；
- 时间；
- 状态；
- 是否属于群组；
- 是否参与连接。

形态根据类型变化，不统一为同款矩形卡。

## 10.2 Fragment Cluster

用于：

- 城市群；
- 时间群；
- 地点群；
- 事件群；
- 发现支撑集合。

要求：

- 内部相对位置稳定；
- 群组轻微呼吸；
- 聚焦时扩散或靠近；
- 不持续随机碰撞。

## 10.3 Fragment Lens

视觉上像“将一个碎片从世界中提起观察”。

结构：

- 背景世界变暗但仍可感知；
- 碎片缩略居上；
- 数据字段分层；
- 关系使用小型节点；
- 主按钮“查看原件”；
- Bottom Sheet 高度 70%–88%。

不做全屏表单。

## 10.4 Scene Visual

- 一次事件；
- 时间轨；
- 2–4 个原件；
- 前后事件；
- 图片主导；
- 不使用发现式大标题。

## 10.5 Place Visual

- 地点节点；
- 多次到访沿时间展开；
- 小地图；
- 同一地点照片并置；
- 不是点评卡。

## 10.6 Connection Visual

- 明确节点两端；
- 时间/空间距离；
- 状态线；
- 证据；
- 不用普通黑卡加一段文字。

## 10.7 Discovery Visual

- 一个发现对应一个碎片关系构图；
- 先原件，后标题；
- 支撑集合比装饰更重要；
- 首屏只一个主动作。

## 10.8 User Authored Block

- 暖白/米色；
- 轻微纸张感；
- 明确“你的文字/用户命名”；
- 与 AI 冷灰观察分开；
- 可显示关联原件缩略。

## 10.9 Evidence Block

固定结构：

- 时间；
- 地点；
- 媒介；
- 支持证据；
- 缺口；
- 来源入口。

避免大段证据散文。

# 13. 当前实现边界与未来技术参考

## 13.1 当前工程约束

当前仓库使用 vanilla HTML、CSS 与 JavaScript。视觉结果和交互质量是强制要求；本章节提到的框架或库不是当前版本的安装要求，也不授权 Coding Agent 重写现有架构。

当前优先使用：

- semantic HTML、CSS variables、CSS transition / keyframes；
- Web Animations API；
- IntersectionObserver、ResizeObserver、Pointer Events；
- `requestAnimationFrame` 与 FLIP；
- SVG path；
- Canvas 2D；
- 项目已存在的 globe.gl、Three.js、MapLibre 与 lottie-web 能力。

当前不得仅因为本文提到某一库就引入 React、Motion / Framer Motion、React Three Fiber、Drei、Rive、XState 或其他新运行时依赖。完整迁移门槛以 [`AGENTS.md`](../AGENTS.md) 为准。

## 13.2 当前可实现的对应方式

| 体验目标 | 当前 vanilla 实现 |
| --- | --- |
| 页面、图片与节点显影 | CSS transition / keyframes、Web Animations API、IntersectionObserver |
| 共享元素与布局过渡 | `getBoundingClientRect()` + FLIP |
| 关系线与状态路径 | SVG `path`、`stroke-dasharray` / `pathLength`、Web Animations API |
| 轻量粒子与碎片背景 | Canvas 2D + `requestAnimationFrame`，离屏暂停 |
| 世界地球 | 已有 globe.gl / Three.js；按需渲染、降低 DPR、低性能静态降级 |
| Else 状态 | 有限状态对象 + CSS class；透明 WebP 或现有 lottie-web 资产 |
| Bottom Sheet / 抽屉 | 原生 DOM、Pointer Events、CSS transform |
| Reduced Motion | `matchMedia('(prefers-reduced-motion: reduce)')` |

## 13.3 未来可评估的技术方案

以下仅在已证明原生实现无法合理满足目标、已说明回归风险与 fallback、并获得用户单独批准后评估：

### Motion

可用于页面显影、Fragment Lens、Bottom Sheet、节点布局过渡、关系线、共享元素和轻微滚动联动。

### React Three Fiber

可评估于世界地球和高级全碎片远景。若未来采用，仍须满足：DPR 最大 1.5、离屏暂停、按需渲染、低性能静态降级、不在后台持续运行。

### Rive

可评估为 Else 的状态机资产。资产未完成时，优先使用 5 张透明 WebP 配合原生动画；不得临时拼接大量低质量 Lottie。
