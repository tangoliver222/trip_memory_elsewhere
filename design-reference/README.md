# Elsewhere Visual Reference Package

**用途：** 让 Gemini 在写生产代码之前独立提出可审查的高保真视觉真相；让 Codex 只把已批准的构图、层级与动效实现为生产页面。  
**不是：** 通用灵感图库、可复制模板集，或让模型随意混搭的“氛围板”。

> **先批准视觉真相，再写生产实现。**

## 1. 工作流

```text
页面契约
↓
Gemini 独立视觉原型
↓
用户批准构图和心流
↓
Codex 搭建或重构生产页面
↓
Gemini 根据生产截图做视觉审查
↓
Codex 只修明确差异
```

### 职责边界

- **页面契约：** 从 `docs/ELSEWHERE_PAGE_LOGIC_MAP_v1.md` 读取。它决定页面为什么存在、入口、唯一主动作和离开方向。
- **Gemini：** 产出高保真视觉原型，或对生产截图做差异审查。它不改生产代码，不创造新的产品结构。
- **用户：** 批准或否决构图、内容层级、原件与空间的关系、心流节奏。
- **Codex：** 只实现批准后的视觉方案；审查阶段只修复 Gemini 明确列出的差异，不再自行改造设计。

## 2. 每次 Gemini 任务的输入顺序

1. 目标页面的页面契约；
2. `docs/DESIGN_BRIEF.md`；
3. `docs/Elsewhere_Visual_Design_System_v3.0.md` 中对应页面规范；
4. 本目录中对应的 `good/` 与 `bad/` 参考；
5. `assets/` 中可使用的真实原件与 `fixtures/manifest.json` 指向的数据；
6. 本次任务的页面状态与 390 × 844 目标视口。

不要要求 Gemini 参考整份历史前端或把旧版截图当成完整页面方案。它应只使用写明的可保留优点，并主动避开反例。

## 3. Gemini 原型输出契约

每次只处理一个页面和一个状态。输出必须包含：

1. `390 × 844` 的高保真静态原型；
2. 页面名称、对象类型、页面密度、唯一视觉焦点和唯一主动作；
3. 原件 → 时间/地点 → 连接 → AI 观察 → 用户动作的显影顺序；
4. 使用了哪些 asset / fixture，以及哪些原件仍缺失；
5. 不超过三条仍需用户判断的视觉选择；
6. 设计审查时的差异清单：`区域 / 当前 / 目标 / 严重级别 / 可验收条件`。

禁止输出：代码、泛化的 UI 套件建议、未经 PRD 支持的新页面、用 AI 散文掩盖信息层级，或无法回到原件的“漂亮卡片”。

## 4. 正例：保留局部原则，不照抄页面

### `good/world-globe-spatial-composition.png`

**保留原因：**

- 地球是完整的空间主角，而非嵌在统计卡中的插图；
- 城市点数量克制，城市之间有足够黑场与距离；
- 地球、城市入口和最近旅程形成由空间到内容的连续动线；
- 原件缩略位于次级层，不抢走地球的首屏焦点。

**不得照抄：**

- 旧版三 Tab 结构与旧导航图标；
- “走过的地方还在发微光”类主导情绪文案；
- 大量药丸式城市标签、Plus 按钮和双 Ellipsis；
- 将 Else 固定为常驻桌宠或叠加第二个实例。

### `good/city-capsule-original-collage.png`

**保留原因：**

- 异构照片以有前后关系的拼贴出现，能感到原件而不是模板封面；
- 图片边缘的克制颗粒化消融让原件进入黑场，不像规整卡片；
- 城市标题、时间轨和关系线能让读者从画面走向证据；
- 大面积黑色空间有私密感，而不是科技面板。

**不得照抄：**

- “你在曼谷的日子，慢慢有了自己的半径”这种替用户下结论的巨型文案；
- 把整张关系图塞在章节末尾；
- 过多全局粒子、旧顶部工具按钮与旧页面结构；
- 把所有章节固定成同一种拼贴构图。

## 5. 反例：禁止复现的模式

### `bad/me-oval-hero-and-leading-copy.png`

**禁止复现：**

- 用巨型衬线句子预设用户情绪；
- 把原始照片锁进巨大椭圆裁切，切断画面的空间；
- 文字直接压在高亮照片上而缺乏可读性处理；
- “我的”页面变成自我疗愈海报，而不是用户书写与控制空间。

### `bad/world-low-contrast-globe-dashboard.png`

**禁止复现：**

- 地球低对比到城市与地形都无法识别；
- 把地球变成一块灰色圆形组件，和页面空间没有连续关系；
- 用“3 座城市 · 172 个碎片”这类统计替代真实入口；
- 地球下方堆叠最近归档和纵向信息行，形成 Dashboard。

### `bad/archive-generic-list.png`

**禁止复现：**

- 世界或全部碎片退化为普通垂直列表；
- 标题、统计、Tab、列表行使用同一种标准 UI 语法；
- 背景关系线只是随机装饰，和具体原件无关；
- 城市、地点、线索被做成同一种行结构。

### `bad/archive-circular-media-and-prose.png`

**禁止复现：**

- 将所有照片裁进完美圆形；
- 用“这些地方仍替你保存细节”一类文艺标题抢在原件前；
- 用“全部 / 地点 / 线索”胶囊 Tab 取代对象层级；
- 把城市条目做成相同的图、标题、描述和箭头组合。

## 6. 可用资产与缺失资产

`assets/` 内的文件是当前原型可直接引用的真实或已确认视觉资产。

| 文件 | 用途 | 不可用作 |
| --- | --- | --- |
| `bangkok-photo-01-ari-morning.jpg` | Ari 的日间主照片、地点/时间重复证据 | 通用城市 Hero 背景 |
| `bangkok-photo-02-riverside.jpg` | 河岸、渡船、傍晚的事件主体 | 任何城市的装饰照片 |
| `bangkok-photo-03-old-town.jpg` | 街道与市场的探索性补充原件 | 重复填充同一天素材 |
| `bangkok-photo-04-ari-coffee.png` | Ari 的第二张日间证据 | 独立成一段 AI 结论 |
| `else-idle.png` / `else-idle-source.png` | Else 的静态 idle 形态与材质参考 | 多实例悬浮客服图标 |
| `else-quiet-float.json` | 已有 5 秒 quiet float idle 动画；无状态 marker | reading/found/uncertain/conflict 状态机 |
| `earth-topology.png` / `earth-night.jpg` | 地球的低亮度地理材质参考 | 数据大屏背景或满屏纹理 |

当前**缺少真实原件**：`receipt-01`、`receipt-02`、`ferry-ticket`、`map-screenshot`、`menu`、`market-photo-01`、`chiang-mai-photo-01`、`tokyo-photo-01`。完整缺口以各 fixture 的 `requiredAsset` 为准。这些对象仍存在于 fixture 中，但在用户提供真实素材前：

- 不得生成伪造为用户真实记录的票据、菜单或地图截图；
- 原型可用清晰的“原件待补”或最小文本证据节点表达其位置与状态；
- 用户补充真实原件后，以同名文件加入 `assets/` 并更新 fixture 的 `asset` 字段。

### 缺失原件的原型决定

允许在视觉原型中表达 `requiredAsset`，但它是**证据节点**，不是一张由模型伪造的“用户小票”。

- 形态应保留媒介含义：小票/票据为窄纸张比例，菜单为文字密度较高的纸张比例，地图截图为屏幕比例；
- 仅展示 fixture 中已有的 OCR 片段、日期、商户与状态，例如 `COMMON GROUNDS · 16 OCT · 124 THB`；
- 使用低饱和纸张、边缘不完整和小型标签 `原件待补`，而不是大号空状态、通用文件图标或“待考古”这类诗意占位；
- 它可以参与时间锚定与未决关系，但不能被放大为 Hero，也不能被画成已确认的完整原件；
- 一旦补入真实文件，必须直接替换证据节点，不保留伪装性外观。

## 7. Fixture 规则

- [`fixtures/manifest.json`](./fixtures/manifest.json) 是所有 fixture 的唯一入口；Gemini 不需要读取 `src/main.js`。
- `world.json`、`places.json`、`scenes.json`、`bangkok-fragments.json` 覆盖空间、事件、原件和未安放状态；总量与代表性原件分开表达。
- `relations.json` 定义连接状态及证据，不能把建议状态画成已确认；`discoveries.json` 定义发现的支撑集合，不是可直接展示的 AI 文案。
- `user-writings.json`、`intake-and-inbox.json`、`else-context.json` 覆盖“我的”、导入/收件箱与 Else 的真实内容层。
- 先根据 fixture 排原件、时间、地点和连接，最后才展示克制观察。
- 不复制同一个 asset 假装不同日期；未提供图片的对象必须保持未决或文字证据状态。

## 8. 视觉审查清单

Gemini 审查生产截图时逐项判断：

1. 页面是否先让用户看到真实碎片，而不是标题、统计或 AI 结论？
2. 是否只有一个视觉焦点和一个主动作？
3. 原件、时间地点、连接、AI 观察、用户文字是否层级清楚？
4. 是否错误复现了反例中的椭圆/圆形裁切、通用列表、Dashboard、胶囊 Tab 或文艺说教？
5. 粒子是否来自原件边缘、关系路径或 Else 状态，而不是随机星空？
6. 世界、发现、我的是否拥有不同的视觉职责？
7. 390 × 844 下主动作、导航、Else 和原件是否都可见且不重叠？
8. 是否忠实实现已批准原型，而不是“看起来差不多”？

## 9. Gemini 提示模板

```text
你是 Elsewhere 的视觉负责人。请为【页面名称 / 状态】提出一张 390 × 844 的高保真移动端视觉原型，不写代码。

页面契约：读取 docs/ELSEWHERE_PAGE_LOGIC_MAP_v1.md 的对应条目。
视觉约束：读取 docs/DESIGN_BRIEF.md 与 docs/Elsewhere_Visual_Design_System_v3.0.md。
参考包：读取 design-reference/README.md；使用指定 good/ 的优点，主动避开 bad/ 的模式；只使用 assets/ 与 fixtures/ 中存在的原件和事实。

必须：原件先于 AI；一个视觉焦点；一个主动作；所有关系可追溯；未决保持未决；Else 只有一个实例。
禁止：Dashboard、Web3/霓虹、通用玻璃卡、圆形照片列表、巨型情绪标题、伪造缺失原件、创建新的产品页面。

交付：原型图 + 焦点/主动作/显影顺序/使用资产/未决项说明。等待用户批准后再进入生产实现。
```
